# VitalityJob

VitalityJob — решение задачи КАНТКОД «Прозрачная вакансия». Сервис проверяет описания вакансий Калининградской области и помогает редактору подготовить конкретные вопросы работодателю. Для каждого замечания отчёт показывает, какое условие требует уточнения, на какие данные опирается проверка и что стоит исправить.

## Проверочный режим для жюри

Потребуются Node.js 22+, Bun 1.3+ и Ollama. Интерфейс и сервер написаны на Next.js и TypeScript, стили — на SCSS. PostgreSQL используется в рабочем режиме для хранения каталога.

Запустите Ollama и выполните из корня репозитория:

```sh
bun install --frozen-lockfile
ollama pull qwen2.5:7b
bun run analyze:json examples/vacancies.json reports/check.json
```

Модель Qwen2.5 7B работает на компьютере через Ollama. Для анализа достаточно установленной модели. База данных, аккаунт облачного ИИ и API-ключи для этого запуска не требуются. Интернет нужен для установки зависимостей и загрузки модели. [Ollama для Windows](https://docs.ollama.com/windows) · [Qwen2.5 7B](https://ollama.com/library/qwen2.5:7b)

[Входной пример](examples/vacancies.json) содержит 13 учебных вакансий на двух страницах. [Образец отчёта](examples/report.json) показывает структуру результата. Файл `reports/check.json` содержит результат запуска модели на вашем компьютере.

Чтобы проверить свой набор, замените путь к входному файлу:

```sh
bun run analyze:json path/to/input.json reports/check.json
```

[Сценарий проверочного режима](scripts/analyze-json.ts) принимает в UTF-8 один JSON-ответ API с массивом `results.vacancies` или массив таких ответов. Он обрабатывает все уникальные ID из файла без обращения к порталу.

Если в окружении уже задан другой ИИ-провайдер, укажите локальную модель перед запуском. Пример для PowerShell:

```powershell
$env:AI_BASE_URL = 'http://127.0.0.1:11434/v1'
$env:AI_MODEL = 'qwen2.5:7b'
bun run analyze:json examples/vacancies.json reports/check.json
```

## Рабочий режим

Источник данных — открытый API «Работа в России», код региона Калининградской области — `39`. Импорт получает страницы автоматически и сохраняет актуальный отчёт в PostgreSQL. [API вакансий региона 39](https://opendata.trudvsem.ru/api/v1/vacancies/region/39)

Создайте базу PostgreSQL. Подойдёт локальная база или Neon. Скопируйте [шаблон окружения](.env.example) в `.env` и заполните параметры:

| Параметр               | Значение                                                                                                                                                                      |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`         | Строка подключения к PostgreSQL. Для Neon скопируйте строку из панели базы.                                                                                                   |
| `CRON_SECRET`          | Случайный секрет для ручного и автоматического запуска импорта.                                                                                                               |
| `VACANCIES_SOURCE_URL` | URL источника. По умолчанию используется API региона 39.                                                                                                                      |
| `VACANCIES_LIMIT`      | Максимум записей за запуск, от 1 до 500. В шаблоне задано 5 для первой проверки. Для импорта двух страниц укажите, например, 21. На странице API запрашивается до 20 записей. |
| `AI_BASE_URL`          | Для локальной Ollama укажите `http://127.0.0.1:11434/v1`.                                                                                                                     |
| `AI_MODEL`             | Для локальной проверки укажите `qwen2.5:7b`.                                                                                                                                  |

Храните строку подключения и секрет в `.env`. Файл исключён из Git. Случайное значение для `CRON_SECRET` можно создать командой:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Запустите Ollama, затем подготовьте хранилище и запустите сайт:

```sh
bun run db:setup
bun run dev
```

Откройте [каталог](http://localhost:3000). После первого успешного импорта появятся вакансии и кнопка скачивания отчёта. При запуске в режиме разработки без базы на главной открывается учебный каталог.

### Ручной запуск импорта

Оставьте сервер Next.js и Ollama запущенными. Во втором окне PowerShell из корня репозитория выполните:

```powershell
$importCommand = @'
fetch('http://127.0.0.1:3000/api/cron/process', {
  method: 'POST',
  headers: { Authorization: 'Bearer ' + process.env.CRON_SECRET },
  signal: AbortSignal.timeout(290000)
}).then(async response => {
  console.log(response.status, await response.text())
  if (!response.ok) process.exitCode = 1
}).catch(error => {
  console.error(error.message)
  process.exitCode = 1
})
'@

node --env-file=.env -e $importCommand
```

Ответ `200` содержит `count`, `pages` и `generatedAt`. Код `401` означает, что стоит сверить `CRON_SECRET` клиента и сервера. Код `409` означает, что обновление уже выполняется. При `503` ответ называет этап сбоя. Если первая обработка на локальной модели упирается в лимит запроса в 280 секунд, уменьшите `VACANCIES_LIMIT`.

### Автоматический запуск в Windows

Задача Планировщика Windows вызывает тот же обработчик. Следующая конфигурация задаёт ежедневное обновление в 06:00 по времени компьютера. Выполните её в том же окне PowerShell, где задана переменная `$importCommand`. Меняйте время в параметре `-At`. [Документация Планировщика Windows](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/register-scheduledtask)

```powershell
$scheduledCommand = $importCommand -replace '\r?\n', ' '
$actionParams = @{
    Execute = (Get-Command node -CommandType Application).Source
    Argument = '--env-file=.env -e "' + $scheduledCommand + '"'
    WorkingDirectory = (Get-Location).Path
}
$definition = @{
    TaskName = 'VitalityJob Import'
    Action = New-ScheduledTaskAction @actionParams
    Trigger = New-ScheduledTaskTrigger -Daily -At '06:00'
    Settings = New-ScheduledTaskSettingsSet -MultipleInstances IgnoreNew
    Principal = New-ScheduledTaskPrincipal -UserId (whoami.exe) -LogonType Interactive -RunLevel Limited
}
Register-ScheduledTask @definition
```

В момент запуска пользователь Windows должен быть в системе, а Next.js и Ollama должны работать. Для проверки выберите «Выполнить» у задачи `VitalityJob Import` и проверьте время обновления каталога.

## Как устроена проверка

Рабочий импорт начинается в [обработчике `/api/cron/process`](src/app/api/cron/process/route.ts). Он вызывает [сценарий обработки](src/services/analysis/runProcessing.ts), который загружает страницы API, объединяет вакансии по ID, запускает анализ и сохраняет результат в PostgreSQL. Для неизменившихся входных данных используются сохранённые результаты. При сбое источника сервис сообщает об ошибке и сохраняет последний успешный отчёт. Каталог показывает готовые результаты анализа.

[Анализатор](src/services/analysis/analyzeVacancies.ts) используется и при импорте, и при работе с локальным файлом. Он сопоставляет текст вакансии со структурированными полями и проверяет название, обязанности, требования, оплату, график, место работы и тип занятости. Правила выявляют пропуски и часть числовых противоречий. Qwen проверяет смысл формулировок и предлагает уточнения. Перед добавлением замечания сервис сверяет его цитаты с исходными полями.

## Формат JSON-отчёта

Общий отчёт скачивается из каталога или через `GET /api/reports`, отчёт по вакансии — из карточки или через `GET /api/reports?id=<id>`.

Корневые поля `version`, `generatedAt`, `source`, `model` и `pages` содержат версию формата, дату формирования, источник, имя модели и число входных страниц. В `vacancies` лежит по одному элементу на ID. Поле `url` содержит ссылку на вакансию или `null`. Пустой массив `issues` означает, что по проверенным условиям замечаний нет.

| Поле замечания   | Содержимое                                                                                                                       |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `topic`          | Тема проверки. `title`, `duties`, `requirements`, `pay`, `schedule`, `location` или `employment`.                                |
| `kind`           | Тип. `missing` — пропуск, `ambiguous` — неоднозначность, `contradiction` — противоречие.                                         |
| `evidence`       | Исходное поле `field` и цитата или значение `quote`. У пропуска `quote` пустая. У противоречия приводятся два исходных значения. |
| `problem`        | Какой информации недостаёт или что мешает однозначно понять условие.                                                             |
| `recommendation` | Какой вопрос задать работодателю или что уточнить в описании.                                                                    |

## Дополнительный сценарий

Редактор может открыть [«Проверить свой JSON»](http://localhost:3000/analyze) и загрузить одну вакансию до 128 КБ. Поддерживаются исходный JSON вакансии и ранее скачанный отчёт по одной вакансии. Для отчёта сервис ищет исходные данные по ID в каталоге или по ссылке на «Работу в России». Локальная модель повторяет проверку, а страница показывает замечания и отдельную карточку «Как исправить замечания». Результат можно скачать в JSON.
